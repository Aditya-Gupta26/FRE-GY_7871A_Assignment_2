# Step 6: Collecting Market Data

While the document scrapers ran, we built the market-data side of the pipeline in parallel — the four indicators the assignment specifies, plus the control variable used later to isolate "the words" from "the decision."

## `src/fetch_market_data.py`

**What it does:**
- Pulls **DXY** (`DX-Y.NYB`), **Russell 1000 Growth** (`IWF`), and **Russell 2000 Value** (`IWN`) daily closes from Yahoo Finance via `yfinance`.
- Pulls **10s2s spread** (`T10Y2Y`), **1-year Treasury yield** (`DGS1`), and **3-month T-bill yield** (`DGS3MO`) from FRED via the `fredapi` package, authenticated with the key you provided (read from `.env`, never hardcoded).
- Computes `GROWTH_MINUS_VALUE` as the *difference in daily returns* between IWF and IWN — not the difference in price levels. This detail comes directly from the assignment's own definition ("Russell 1000 Growth **return** minus Russell 2000 Value **return**") and from "Parsing the Fed"'s own methodology appendix, which spells out the same return-spread construction.
- Joins everything into one daily panel spanning January 2018 through late September 2026 (with buffer on both ends so the very first and very last events in our window still have a valid "day before" and "day after" to compare against).

**Why it was necessary:** these are the exact indicators the assignment specifies, from the exact sources it names (Yahoo for DXY/IWF/IWN, FRED for the yield series) — this script is a direct, literal implementation of "The data" section of the assignment sheet, not a design choice we had latitude on.

**A deliberate choice worth flagging:** we pulled DGS3MO (the 3-month bill) even though it's explicitly *not* one of the four indicators to explain — it's the control variable the assignment specifies for the regression step, used to strip out "the rate decision itself" from "how it was worded." Fetching it here, alongside the four real indicators, meant [Step 11](11-master-dataset-and-regressions.md)'s regression script didn't need a second, separate data-fetching step later.

## Result

A combined panel of **2,270 daily rows** (Jan 2018 – Sept 11, 2026) saved to `data/processed/market_panel.csv` (gitignored, per the assignment's "no data files" rule — this is regenerated by re-running the script, not something anyone needs to check into version control).

We also checked the missing-value counts immediately after fetching (83–97 missing days across the six raw series, growing to ~170 for the computed return columns since a single missing day creates two missing return observations). This wasn't a bug — FX/equity markets and the Treasury market don't share an identical holiday calendar (Treasury markets close for some holidays equities don't, and vice versa) — but confirming *why* the gaps existed, rather than shrugging past them, mattered because [Step 10](10-event-study.md)'s event-study logic has to handle exactly this kind of calendar mismatch correctly, or it would silently compare the wrong two days around some releases.
